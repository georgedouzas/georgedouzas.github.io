# Spec Delta

## Purpose

Ensures every figure in the tutorial is produced by a committed, re-runnable SageMath script from the same
mathematical objects the text and the proofs use, so figures are reproducible and cannot drift from the results.

## ADDED Requirements

### Requirement: Every figure has a generating script
Each figure in the tutorial SHALL be produced by a committed script, and running that script SHALL regenerate the
figure file. The tutorial SHALL NOT embed hand-drawn or externally sourced images.

#### Scenario: Figure regeneration
- **WHEN** a figure's generating script is run on a clean checkout
- **THEN** it writes the figure file at the path the document references, and the document renders with it

#### Scenario: Image without a script
- **WHEN** the document references an image file that no committed script produces
- **THEN** the build's figure check fails and names the image

### Requirement: Figures are drawn from the verified objects
A figure that depicts a computed object (a metric, a vector field, a spectrum, a potential) SHALL be generated from
the same explicit expressions that appear in the text and in the Lean statements.

#### Scenario: Killing vector fields on the sphere
- **WHEN** the tutorial plots the Killing vector fields of `S^2`
- **THEN** the plotted components are the components displayed in the text and verified in Lean

#### Scenario: Higgs potential of the reduced theory
- **WHEN** the tutorial plots the four-dimensional scalar potential from CSDR
- **THEN** the plotted function is the displayed potential, and its plotted minimum agrees with the verified minimum

### Requirement: Required figures are present
The tutorial SHALL contain at least these figures: a chart on `S^2` with coordinate lines, the circle fibre over
spacetime for the abelian Kaluza-Klein ansatz, the Killing vector fields on `S^2`, the Hopf fibration
`SU(2) -> S^2` as the coset picture, the Kaluza-Klein mass tower, and the CSDR scalar potential.

#### Scenario: Figure inventory
- **WHEN** the rendered tutorial's list of figures is inspected
- **THEN** each required figure is present in the chapter where its concept is introduced

### Requirement: Every chapter has Sage-generated figures
Every chapter whose material can be visualised (a space, a field, a spectrum, a potential, a group orbit, a coset
decomposition, a flow) SHALL contain at least one figure generated by a Sage script, and chapters with several
visualisable objects SHALL illustrate each of them.

#### Scenario: Chapter inventory
- **WHEN** the figure check lists the figures per chapter
- **THEN** every chapter of the mathematics, physics, Kaluza-Klein and CSDR parts has at least one figure, and a chapter without one is listed with the reason recorded in the registry notes

#### Scenario: A coset chapter
- **WHEN** the coset-space chapter is rendered
- **THEN** it shows at least the Hopf fibration, the coset decomposition of `so(3)` as the tangent plane at the pole with the isotropy rotation, and the orbits of a one-parameter subgroup on the sphere

### Requirement: Sage computations use Sage's dedicated modules
Figure scripts, exercise solutions and oracles SHALL compute geometric and algebraic objects with Sage's dedicated
modules where one exists (SageManifolds for manifolds, charts, metrics, connections, curvature and vector fields;
the Lie algebra, root system, Weyl character ring and group modules for algebra and representations), rather than
with hand-coded formulas.

#### Scenario: Curvature in a script
- **WHEN** a script computes Christoffel symbols or curvature
- **THEN** it builds a SageManifolds manifold with a chart and a metric and calls the metric's methods, and the result is what the text displays

#### Scenario: Branching rule in a script
- **WHEN** a script computes a branching rule or a tensor product decomposition
- **THEN** it uses the Weyl character ring (or an equivalent Sage representation-theory module), and the text displays its output

### Requirement: Figure captions describe content and provenance
Each caption SHALL state what is depicted, the coordinates or parameters used, and the name of the generating
script.

#### Scenario: Caption inspected
- **WHEN** a reader reads a figure caption
- **THEN** it names the depicted object, the parameter values and the generating script

### Requirement: Figures render in every output format
Every figure SHALL appear correctly in both the HTML and the PDF output.

#### Scenario: PDF and HTML rendering
- **WHEN** the tutorial is rendered to HTML and to PDF
- **THEN** every figure appears in both outputs at legible size, with vector format where the plot is two-dimensional

### Requirement: Interactive figures where feasible

Examples that draw surfaces, vector fields, orbits or potentials SHALL provide an interactive HTML figure produced
by the Sage script (threejs for 3D, Plotly.js with Sage-written JSON data for 2D), included by a shortcode, with
the static image as the PDF fallback.

#### Scenario: Interactive surface
- **WHEN** a Sage script produces a 3D scene
- **THEN** it also saves the threejs HTML and the chapter embeds it in the HTML output
